### A6. State the evaluation protocol: closed-set enrollment

**Problem.** `data/split_lasalle/train` and `data/split_lasalle/test` contain the **same
28 identity folders** (verified with `comm -12`). The split is image-disjoint but
subject-shared — i.e. **closed-set enrollment**. That is the *correct* protocol for an
access-control gate (you enroll exactly the people you admit), but no document says so,
and a reviewer will read "TAR 98.21%" as open-set generalization unless told otherwise.
Generalization to unseen identities is only ever measured as impostor rejection
(LFW legs); open-set identification of novel genuine identities is never measured.

**Change.**
- `docs/PAPER.md` §3.6 (Datasets/protocol, near Table 1): add one short paragraph, e.g.:
  > *All identification and verification numbers on LS-DB1/LS-DB2 use closed-set
  > enrollment: the gallery and probe sets share the same 28 identities and are
  > image-disjoint (10 gallery / 2 probe images per identity). This mirrors the
  > deployment (a gate admits only enrolled subjects). Robustness to identities never
  > seen at enrollment is measured solely as impostor rejection against the LFW legs;
  > open-set identification of novel genuine identities is out of scope.*
- `README.md` (Datasets section, ~line 92): one sentence naming the protocol closed-set.

### A7. Single source of truth for the hybrid gate thresholds

**Files:** `src/hybrid/gate.py`, `src/hybrid/thresholds.json`

**Problem 1 — duplicated constants.** `GateThresholds` hardcodes the frozen values as
dataclass defaults (`gate.py:36-38`):
```python
tau_accept: float = 73.04   # <= this LBPH distance => confident accept
tau_reject: float = 76.85   # >= this LBPH distance => confident reject
margin_min: float = 0.05    # min relative top1<->top2 gap (d2-d1)/d1 to trust LBPH
```
The same three values live in `src/hybrid/thresholds.json` (the artifact with the
provenance block that the evidence matrix SHA-256-hashes). Anyone recalibrating updates
the JSON; code paths that construct `GateThresholds()` without going through
`load_thresholds()` silently keep the stale literals. Two sources of truth for the
*frozen anchor* is exactly the failure mode the freeze protocol exists to prevent.

**Change.** In `gate.py`, load defaults from the JSON once at import:
```python
_THRESHOLDS_JSON = Path(__file__).with_name("thresholds.json")

def _frozen_defaults() -> dict:
    try:
        return json.loads(_THRESHOLDS_JSON.read_text())["gate"]
    except (OSError, KeyError, ValueError):
        return {"tau_accept": 73.04, "tau_reject": 76.85, "margin_min": 0.05}  # last-resort fallback
```
and use `field(default_factory=...)`-style wiring (or build the default instance via
`GateThresholds.from_dict(_frozen_defaults())`). Keep the dataclass frozen; keep
`from_dict` unchanged so `load_thresholds()` callers are unaffected. Match the exact
key path to the JSON's actual schema when implementing.

**Problem 2 — misleading dead metadata.** `thresholds.json`'s
`calibration_stats.lbph_margin` medians are ~7.3e7 (raw chi-square scale) while
`gate.tau_*` are on the normalized 0-100 scale, and `gate.py` never reads
`calibration_stats.lbph_margin` (it uses the *relative* margin 0.05). Two incompatible
scales in one file invite misuse.

**Change.** Add a `"_note"` field inside `calibration_stats`, e.g.
`"_note": "diagnostic only, raw chi-square scale; NOT used by gate.py, which applies the relative margin_min from the gate block"` —
or delete the block if nothing else consumes it (grep first).

**Verify.** `python3 -c "from src.hybrid.gate import GateThresholds; print(GateThresholds())"`
prints values equal to the JSON's; temporarily renaming `thresholds.json` still constructs
the fallback defaults.

### A11. Metric-code guards

**(a) `balanced_accuracy` fake zero.** `src/classical_faces/pipeline.py` `_rates()`
(~line 272-287) returns balanced accuracy `0.0` when either the genuine or impostor
group is empty. On a closed-set test split (no impostors) every report then carries
`"balanced_accuracy_percent": 0.0` (emitted at lines 317, 367, 815), which reads as
"0% accuracy" instead of "not applicable". Change the empty-group case to return `None`
(JSON `null`), and have any Markdown renderers print `N/A`. Check consumers
(`src/benchmark/compare_classical.py`, `aggregate_evaluation_reports.py`,
`scripts/make_report_figures.py`) tolerate `null` — guard with `is not None` where they
format numbers.

**(b) Undeclared symmetry invariant.** `src/independence_common.py:388-403`
`error_pair_report_from_topk()` converts ordered-comparison ranks to unique-pair ranks
via `unique_idx = ceil(rank/2) - 1`, which is only valid if the distance metric is
symmetric (each unordered pair appears exactly twice in the ordered stream). All current
metrics (chi-square, Euclidean) are symmetric, but nothing states or checks the
invariant — an asymmetric metric added later would silently halve the reported FAR.
Add a docstring sentence plus a cheap runtime guard: when materialized pairs are
available, assert that the top-K list contains each unordered pair an even number of
times (or at minimum document the precondition in the function docstring and at the
call sites in `run_lfw_independence.py`).

### B2. Threshold uncertainty across the 10 seeded runs

**Problem.** The lasalle independence tests run 10 seeded iterations
(`src/lbph/independence_test.py:530`, seeds `random_seed + i`, default base 42), but
`src/independence_common.py:aggregate_pairwise_results()` (line 233) **averages each
pair's distance across runs before ranking**. Consequences:
- The published 8th-error-pair threshold (85.88) is a point estimate with no
  uncertainty band, even though 10 runs are sitting in `_raw_runs/`.
- `distance_statistics.std_dev` is the spread **across identity pairs**, not run-to-run
  variance — a reader cannot tell how stable the threshold is under reseeding.
- Mean-before-rank suppresses exactly the tail behavior FAR cares about (the worst
  single-run impostor collision).

**Change (three parts, no re-running needed for the backfill).**
1. **New function** in `src/independence_common.py` (near `aggregate_pairwise_results`):
   `per_run_error_pair_thresholds(runs, k) -> dict` — for each run's 756 distances,
   compute the k-th-smallest (reusing `error_pair_threshold`'s logic), and return
   `{"k": k, "per_run": [...10 values...], "mean": ..., "std": ..., "min": ..., "max": ...}`.
2. **Summary writers**: in `src/lbph/independence_test.py` (~lines 590-615) and the
   eigen/fisher clones, add a `per_run_thresholds` block to `summary.json`, and record
   `"random_seed_base"` (currently the seed is *used* but never written anywhere —
   an artifact cannot be traced to its seed).
3. **Backfill utility**: extend `scripts/plot_independence_comparisons.py` (or add
   `scripts/per_run_thresholds.py`) to read the *committed*
   `reports/independence/*/_raw_runs/run_*/comparisons.csv`, compute the per-run 8th-pair
   thresholds, and print/append the block — so the committed lasalle artifacts gain the
   stability statement without re-running. Surface the result as one line in
   METRICS.md Table 3 and PAPER §4.1, e.g.
   `8th-pair threshold across 10 seeded runs: mean X.XX ± Y.YY (range A.AA–B.BB), normalized`.
   Report both scales (raw + normalized); note that per-run normalization uses that
   run's own max, so prefer the raw-scale spread as the primary stability number.

**Verify.** Backfill on `reports/independence/lbph_lasalle/_raw_runs/` prints 10 values
clustered near 85.9 normalized / 21.35 raw; the mean-of-per-run thresholds should be
close to (but not necessarily equal to) the committed mean-before-rank 85.88 — if they
differ materially, that is itself a finding to report, not to hide.

### B4. Machine-independent reported distributions

**Problem.** In streaming mode, the published percentiles/median/histograms are computed
from a **subsample** whose size comes from the hardware tier:
`src/independence_streaming.py:246-247` does `step = max(1, total // sample_cap)` and
samples `raw[::step]`, with `sample_cap` derived in `main.py:compute_hardware_profile()`
(line ~247) from detected RAM/CPU. The same dataset therefore yields different published
distribution figures on different machines (the top-K error-pair *threshold* is exact and
unaffected — only the descriptive stats and plots drift). Which code path even runs
(exact vs streaming) is also hardware-gated via `streaming_threshold` (line ~248).

**Change.**
1. Fix `sample_cap` to a constant default in the analysis code (e.g. 2,000,000) with an
   explicit CLI override; the hardware profile may still cap *memory/chunking*, but must
   not silently change the statistical sample.
2. Whenever sampling was used, record `{"sample_cap": ..., "stride": ..., "sampled_n": ...}`
   in the summary next to the existing `percentiles_sampled` flag, so any figure built
   from a sampled distribution is labeled as such.
