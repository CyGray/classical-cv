# Pairwise Verification Robustness - Expected Output Guide & Specification

This guide defines the standard expected output format, artifact layout, and reporting protocol for the **1:1 Pairwise Verification Robustness Benchmark** across classical (LBPH) and deep learning (SFace) recognizers.

## 2. Table Layout & Formatting Rules

### A. Metric Focus
- Tables must report the **AR %** (Accuracy Ratio / Verification Accuracy at operating threshold $\tau_{accept}$).
- For LBPH: Operating gate is $\tau_{accept} = 67.0084$ (from `src/hybrid/thresholds.json`).
- For SFace: Operating rule is Cosine $\ge 0.363$ & $L_2 \le 1.0313$.

### B. Column Structure & Ordering
The **Per-Modification Table** must follow this exact 4-column layout:

1. **Col 1 (`Modification Family`)**: Public readable family name matching `/docs/41mods_table` (e.g., *Brightness change*, *Blur*, *Gaussian noise*, *Crop*, *Rotation (large-angle)*).
2. **Col 2 (`Severity Tier & Detail`)**: Severity tier name and value detail (e.g., `Light (+10%)`, `Medium (5×5 mask)`, `Heavy (270° canonical)`).
3. **Col 3 (`LBPH Standalone AR (%)`)**: Standalone LBPH verification accuracy percentage.
4. **Col 4 (`SFace Standalone AR (%)`)**: Standalone SFace verification accuracy percentage.

### C. Family Grouping & Row Sorting
- Rows are grouped by **Modification Family** (17 families corresponding to the 41-modification suite).
- Within each family, rows must be ordered strictly from **Light $\to$ Medium $\to$ Heavy** tiers.
- In PNG exports, horizontal group boundary lines separating modification families must be rendered.

## 2b. Interpreting a flat/low LBPH AR (do not swap metrics)

AR (`Accuracy@tau`) is the mandated reported metric per §2.A — this holds even
when it looks flat or low. Confirmed 2026-08-02 on the full run: LBPH AR sits
at ~50-51% across clean/light/medium/heavy because `FAR = 0.00%` on every row,
which pins `Accuracy@tau = (TAR + 100) / 2` into `[50, 51.13]` regardless of
what a modification does. The real, movable signal in that case is **TAR**
(True Accept Rate — this project's preferred term over GAR going forward,
same quantity, JSON field `gar_percent`; 2.26% clean -> 0.93% heavy, monotone)
— check TAR/FAR before concluding a run is broken. Full TAR-only PNG tables:
`docs/experiments/AR/summary_tar_table.png` and
`per_modification_tar_table.png` (generated by
`scripts/export_tar_png_tables.py`, a TAR-labeled variant of §3's exporter).

If TAR/FAR both look this compressed, verify pipeline correctness first
(detector, crop mode, equalization, dataset copy, threshold family — see
`.claude/skills/robustness-protocol-map` §4b and `cv-workspace-map` §2-3) before
accepting the number. If no bug is found, report AR as spec requires, with
TAR/FAR/EER alongside as the diagnostic explanation — do not substitute a
different operating point (e.g. EER-swept accuracy) as the headline just
because it moves more.

## 2c. FAR-target sweep, 2026-08-02: raising FAR does not rescue LBPH TAR

The 10ppm deployment gate is only ONE point on the impostor-distance curve.
To check whether a looser, still-defensible FAR target would meaningfully
recover LBPH TAR, the impostor-only sweep (`native_predict_scale_yunet.json`'s
methodology) was rerun at six FAR checkpoints against the SAME full LFW1
cross-identity pool (16,522,626 unique pairs), and each resulting threshold
was applied to the genuine LBPH distances already collected in
`accuracy_ratio_verification_full_pairs.csv` (clean baseline + all 41 mods
pooled):

| Target FAR | Raw threshold | Clean TAR | Overall TAR (41 mods) |
|---|---:|---:|---:|
| 10 ppm (= deployed gate) | 67.0333 | 2.26% | 1.43% |
| 100 ppm | 68.8808 | 3.87% | 2.36% |
| 0.1% | 71.1718 | 7.08% | 4.33% |
| 1% | 74.3496 | 14.11% | 9.23% |
| 5% | 77.5943 | 23.99% | 17.26% |
| 10% | 79.5150 | 31.25% | 23.30% |
| EER (unfrozen, reference only) | 85.7090 (clean) / 88.1620 (all mods) | 60.71% | 57.67% |

**Finding: giving up FAR almost entirely still doesn't buy much TAR.** Even at
10% FAR — 1 in 10 impostors falsely accepted, unusable for any real gate — clean
LBPH TAR only reaches 31.25%. This rules out "just pick a looser FAR target"
as a fix: the genuine and impostor LBPH (native `predict_collect` chi-square)
distance distributions on wild LFW overlap heavily across this entire range,
not just at the strict 10ppm gate. Only at EER (FAR also ~39-42%, see the
verification report) does TAR cross 50%, and even then it stays below the
65-75% literature baseline — consistent with that baseline using a different,
more discriminative distance (LBP + Euclidean/metric-learning, not OpenCV's
chi-square `predict_collect`), not just a different operating point. See
`.claude/skills/robustness-protocol-map` (workspace root) for the full
writeup and script locations (`far_sweep_impostor_thresholds.py`,
`far_sweep_tar_report.py`, `export_far_sweep_png_table.py`, all in
`classical-cv/scripts/`).

## 3. Pipeline Execution Workflow

To reproduce or update these standard outputs:

```bash
# 1. Run full 1:1 pairwise verification benchmark (5,749 enrolled, 1,680 probes, 41 mods)
cd classical-cv
python -m src.benchmark.accuracy_ratio_verification \
    --split-manifest data/splits/lfw_ident_split_seed42.json \
    --engines lbph,sface \
    --output-json outputs/benchmark/accuracy_ratio_verification_full.json \
    --output-md reports/benchmark/accuracy_ratio_verification_full.md \
    --pairs-csv outputs/benchmark/accuracy_ratio_verification_full_pairs.csv

# 2. Export AR full-bleed PNG tables (writes docs/experiments/AR/*.png) and update
#    docs/experiments/pairwise-verification/README.md
python scripts/export_verification_png_tables.py

# 3. Export the TAR-only diagnostic variant (writes docs/experiments/AR/*_tar_table.png;
#    does not touch README.md)
python scripts/export_tar_png_tables.py

# 4. (Optional, slow: ~8 min, full LFW1 impostor recompute) FAR-target sweep -
#    see §2c. Only needed if the impostor pool or FAR checkpoint list changes;
#    step 4b/4c are cheap and can rerun any time against the existing sweep.
python scripts/far_sweep_impostor_thresholds.py
# 4b. Merge with genuine TAR from step 1's pairs CSV
python scripts/far_sweep_tar_report.py
# 4c. Export FAR-sweep full-bleed PNG (writes
#     docs/experiments/pairwise-verification/lfw-results/SWEEP/summary-table.png)
python scripts/export_far_sweep_png_table.py
```
